# Фильтр подтверждённости: экспериментальный API

`grounding_guard.verify(question, context, proposal, llm, mode)` выполняет один
структурированный запрос к `llm.chat_completion` и возвращает JSON-совместимый
словарь: `accepted`, `reasons`, `proof`, `messages`, `mode`.

- `chain`: модель проверяет предложенный ответ и всю необходимую цепочку фактов.
- `independent`: модель самостоятельно строит ответ, не получая предложение;
  затем код требует точного совпадения после нормализации регистра, пробелов,
  пунктуации и английских артиклей. Синонимы и псевдонимы не сопоставляются.

Каждый шаг должен иметь дословную непустую цитату из контекста. Проверяются
покрытие всех перечисленных ограничений вопроса, отсутствие пропущенных связей,
неоднозначности и использования внешних знаний. Ошибочный формат ответа
отклоняется; ошибки транспорта передаются вызывающему коду для повторной попытки.

Вызывающий код применяет фильтр только к ответам, восстановленным после UNKNOWN,
и при отказе сохраняет исходный UNKNOWN. Для пересечения двух проверок надо
вызвать оба режима и потребовать `accepted` в обоих. Схема одна и та же, но
сообщения различаются; кэш каждого режима должен учитывать полные сообщения.

Цитата подтверждает наличие текста в контексте, но не доказывает логический
переход автоматически. Полнота разложения и смысловая поддержка остаются
суждениями модели: их надёжность необходимо измерить независимой оценкой.
Модуль не получает эталонные ответы, метки судьи или идентификатор выборки.
Это изолированный эксперимент, не изменение настроек или API основного RAGU.

Офлайн-проверка: `python -m pytest experiments/test_grounding_guard.py --no-cov`.
