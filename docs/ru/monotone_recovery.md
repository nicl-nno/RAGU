# Экспериментальная проверка восстановленных ответов

Эта дополнительная интеграция пока ожидает независимой проверки качества. Она сохраняет каждый ответ, принятый существующим строгим фильтром. Если строгий фильтр отклонил восстановленный ответ, его должны принять и проверка по фрагментам источника, и отдельная проверка полного контекста. Последняя получает вопрос, неизменённый контекст и ответ, без предыдущего доказательства или решения.

```python
from ragu import EvidenceSearchParams

params = EvidenceSearchParams(
    recovery_mode="after_review",
    second_recovery_policy="deeper",
    recovery_guard="monotone",
)
# await engine.query(question, params)
```

По умолчанию фильтр выключен: `off`. Он проверяет только содержательные ответы, восстановленные после первоначального `UNKNOWN`. Первоначальный содержательный ответ сохраняется. При отказе возвращаются исходные ответ, доказательства и контекст поиска. При принятии восстановленный ответ и доказательства сохраняются точно. Потоковая выдача при включённом восстановлении по-прежнему не поддерживается.

Фильтр делает от одного до трёх дополнительных вызовов. `response.payload["answer_guard"]["checks"]["monotone"]` содержит решение строгого фильтра, при необходимости — решение дополнительной проверки, а также все выполненные вызовы с фактическими сообщениями и структурированными результатами. Идентификаторы источников и цитаты подтверждают происхождение текста; смысловую обоснованность оценивает модель, которая может ошибаться. Сохранение принятых строгим фильтром ответов не гарантирует прежнюю точность среди всех выданных ответов.

Три зарегистрированных промпта настраиваются через `engine.update_prompt`: `evidence_guard_monotone_strict`, `evidence_guard_monotone_span` и `evidence_guard_monotone_challenge`. Нужно сохранить зарегистрированные схемы результата: соответственно `Proof`, `SpanProof` и `ChallengeProof`. Несовместимая схема вызывает `ValueError`. Изменённый текст отражается во всех вложенных записях вызовов, но меняет оценённый метод: прежние измерения после этого нельзя переносить напрямую. Все этапы используют настроенную LLM движка.

Воспроизведение без новых вызовов: `experiments/replay_monotone_production.py --root PATH_TO_BENCHMARK --expected-commit COMMIT --output RECEIPT.json`. По умолчанию нужны завершённые результаты обеих выборок. Скрипт проверяет их хеши и воспроизводит все последовательности вызовов без подключения к модели. Выполняется рабочий путь получения и проверки ответа с подстановкой сохранённых первоначального состояния и результата восстановления; сам поиск и промежуточные вызовы восстановления не повторяются.
