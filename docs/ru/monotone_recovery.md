# Проверка восстановленных ответов с дополнительным независимым фильтром

Новый дополнительный фильтр прошёл заранее зафиксированную проверку качества. Он сохраняет каждый ответ, принятый существующим строгим фильтром. Если строгий фильтр отклонил восстановленный ответ, его должны принять и проверка по фрагментам источника, и отдельная проверка полного контекста. Последняя получает вопрос, неизменённый контекст и ответ, без предыдущего доказательства или решения.

![Сохраняем принятые ответы и добавляем независимую проверку остальных](../assets/monotone_recovery.svg)

## Результаты

На MuSiQue были зафиксированы поиск, первоначальные ответы и предложения восстановления. Luna выполняла вызовы метода; Sol отдельно оценивала правильность и подтверждённость контекстом. Новая случайная выборка из 400 вопросов не пересекается с двумя предыдущими аудитами Sol. Отбор выполнялся на 300 вопросах для разработки; итоговая композиция предложена после изучения предыдущих вариантов и зафиксирована до открытия нового аудита. Сам бенчмарк уже изучался, поэтому это не нетронутая внешняя проверка. Старый вариант только с проверкой фрагментов ранее не прошёл контроль качества.

| Метрика | Прежний строгий фильтр | Новый фильтр |
|---|---:|---:|
| Сохранённые восстановления, все 2117 вопросов | 27 / 477 | **63 / 477** |
| ROUGE-L без стемминга, 2117 | 0,41697 | **0,43086** |
| ROUGE-L со стеммингом Porter, 2117 | 0,41992 | **0,43381** |
| Правильных / выданных ответов, новый аудит 400 | 176 / 248 (70,97%) | **184 / 256 (71,88%)** |
| Правильных и подтверждённых контекстом, аудит 400 | 140 | **146** |
| Неправильных ответов, аудит 400 | 72 | 72 |
| Неподтверждённых ответов, аудит 400 | 83 / 248 (33,47%) | **85 / 256 (33,20%)** |

Дополнительная ветка сохранила на 36 предложений больше среди 2117 вопросов. В новом аудите она добавила восемь ответов: все восемь признаны правильными, шесть подтверждёнными, два неподтверждёнными. Поэтому абсолютное число неподтверждённых выросло, хотя их доля снизилась. Неподтверждённость не равна неправильности; это оценки модели, а не факты, удостоверенные человеком.

«Независимая» означает, что проверка не видит предыдущих доказательства и решения. Оба вызова выполняет Luna, поэтому статистическая независимость их ошибок не предполагается. Эти результаты получены на прежнем индексе с BGE; отдельная пересборка с GTE ещё не завершена и сюда не входит. Это не воспроизведение препринта с совпадающим индексом.

Парный бутстрэп, 10 000 повторов, seed 42: прирост ROUGE-L относительно строгого фильтра +0,01389, 95%-й интервал [0,00927; 0,01887]; прирост точности +0,91 процентного пункта [0,33; 1,62]. Изменение доли неподтверждённых −0,26 пункта, интервал [−1,23; +0,76] пересекает ноль. Прохождение порогов по точечным оценкам не доказывает статистически надёжного снижения неподтверждённости или отсутствия ухудшения.

Фильтр всё ещё отклоняет 414 из 477 предложений. В аудите 400 вопросов среди 82 отклонённых предложений восстановления 44 признаны правильными, в том числе 15 — также подтверждёнными. Значительная часть избыточных отказов остаётся. Независимая проверка потребовала 99 новых вызовов на подтверждающей выборке; вместе с повторно использованными вызовами строгого фильтра и проверки фрагментов рабочий метод выполнил бы 1026 проверок для 477 восстановлений.

Проверка реализации: 678 тестов прошли. Воспроизведены все 2417 рабочих траекторий и 1189 последовательных вызовов из кэша — без новых вызовов и расхождений в сообщениях, схемах, ответах, доказательствах, контексте или вложенном аудите. [Краткая квитанция проверки и хеши источников](../assets/monotone_validation.json) указывает полный локальный результат воспроизведения и файлы оценки. Неизменённый [предыдущий отчёт о строгом фильтре](grounded_recovery.md) использует другую выборку аудита: его фактические показатели нельзя смешивать с этой таблицей.

## Настройка и аудит

```python
from ragu import EvidenceSearchParams

params = EvidenceSearchParams(
    recovery_mode="after_review",
    second_recovery_policy="deeper",
    recovery_guard="monotone",
)
# await engine.query(question, params)
```

По умолчанию фильтр выключен: `off`. Он проверяет только содержательные ответы, восстановленные после первоначального `UNKNOWN`. Первоначальный содержательный ответ сохраняется. При отказе возвращаются исходные ответ, доказательства и контекст поиска. При принятии восстановленный ответ и доказательства сохраняются точно. Потоковая выдача при включённом восстановлении по-прежнему не поддерживается.

Фильтр делает от одного до трёх дополнительных вызовов. `response.payload["answer_guard"]["checks"]["monotone"]` содержит решение строгого фильтра, при необходимости — решение дополнительной проверки, а также все выполненные вызовы с фактическими сообщениями и структурированными результатами. Идентификаторы источников и цитаты подтверждают происхождение текста; смысловую обоснованность оценивает модель, которая может ошибаться. Сохранение принятых строгим фильтром ответов не гарантирует прежнюю точность среди всех выданных ответов.

Три зарегистрированных промпта настраиваются через `engine.update_prompt`: `evidence_guard_monotone_strict`, `evidence_guard_monotone_span` и `evidence_guard_monotone_challenge`. Нужно сохранить зарегистрированные схемы результата: соответственно `Proof`, `SpanProof` и `ChallengeProof`. Несовместимая схема вызывает `ValueError`. Изменённый текст отражается во всех вложенных записях вызовов, но меняет оценённый метод: прежние измерения после этого нельзя переносить напрямую. Все этапы используют настроенную LLM движка.

Воспроизведение без новых вызовов: `experiments/replay_monotone_production.py --root PATH_TO_BENCHMARK --expected-commit COMMIT --output RECEIPT.json`. По умолчанию нужны завершённые результаты обеих выборок. Скрипт проверяет их хеши и воспроизводит все последовательности вызовов без подключения к модели. Выполняется рабочий путь получения и проверки ответа с подстановкой сохранённых первоначального состояния и результата восстановления; сам поиск и промежуточные вызовы восстановления не повторяются.
